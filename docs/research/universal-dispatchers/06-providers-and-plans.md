# 06 — Model providers, endpoints and plans (as of 2026-10-20)

## Bottom line

1. Every provider in scope now exposes an **Anthropic Messages endpoint** and publishes a `claude` setup that uses the same env pattern (`ANTHROPIC_BASE_URL` + `ANTHROPIC_AUTH_TOKEN` + per-tier `ANTHROPIC_DEFAULT_*_MODEL` + `[1m]` suffix + `CLAUDE_CODE_AUTO_COMPACT_WINDOW`). So one generic "`claude -p` + endpoint profile" dispatcher can reach Z.ai, DeepSeek, Kimi, MiniMax, Qwen, OpenRouter, Fireworks and a local Ollama. Most of them also expose OpenAI Chat Completions and, increasingly, the **Responses API** (the protocol Codex speaks) [docs: per-provider rows in §1.1].
2. **What blocks a headless dispatcher is the terms of service, not the protocols.** Kimi Code and the Alibaba Coding/Token Plans say in writing that they are for **interactive use only** and forbid scripted or non-interactive use. Z.ai's GLM Coding Plan limits use to listed tools and bans "bulk or automated usage on behalf of others", but says nothing about headless use by the subscriber. MiniMax's M Plan says it is "designed for individual, interactive developer use" without an explicit ban. **Pay-as-you-go keys carry no tool or interactivity restriction**, so they are the clean default for automated dispatch. Plan keys should be opt-in, set per provider, and show the warning that applies.
3. **Keys are now typed, and the key type decides billing**: Z.ai (from 2026-10-16), MiniMax (Subscription Key vs API Key), Alibaba (`sk-sp-` vs `sk-`) and Kimi (Kimi Code console vs Open Platform). A key on the wrong endpoint fails or bills pay-as-you-go silently, so a provider profile has to store the endpoint and the key type together.
4. **Price per typical agent request** (same token mix for every model; see §4) [local-run, from cited list prices]: DeepSeek Flash $0.00035–0.0007 < GPT-6 Luna / Haiku 5.5 ≈ $0.00067 < MiniMax M3.1 Flash ≈ $0.001 ≈ Qwen3.8 Flash < GLM-5.3-Flash $0.0017 < DeepSeek V4 Pro $0.0019–0.0038 ≈ MiniMax M3 < GPT-6.1 Sol $0.008 < Kimi K2.7 Code $0.011 < GLM-5.3 ≈ Qwen3.8 Max ≈ Opus 5.5 ≈ $0.015–0.016 < Kimi K3 ≈ $0.020.
5. **Quality evidence for open-weights coding models is thin and comes from vendors.** The only independent agentic-coding number I found: GLM-5.3 (max, Claude Code) scores 32.4% ±1.5 on Terminal-Bench 3.0, 4th behind Opus 5, GPT-5.6 Sol and Fable 5 (Snorkel leaderboard, newest entry 2026-08-14). Kimi K3, DeepSeek V4 Pro, MiniMax M3 and Qwen3.8 Max have no entry there. Other independent agentic-coding leaderboards on the same Snorkel site do list them: Agentic Coding 2.0 (pass@1) Kimi K3 26.1%, GLM 5.3 24.9%, DeepSeek V4 Pro 14.8%, Qwen 3.8 Max 14.7% (77.7% agent timeouts), against GPT-6 Astra 47.6% and Opus 5.5 40.4%; SWE-bench CLI (pass@1) Qwen 3.8 Max 4.9%, Kimi K3 4.1%, GLM 5.3 3.5%, DeepSeek V4 Pro 2.3%, against Opus 5.5 16.6%; Terminal-Bench 4.0 (Claude Code harness) GLM-5.3 41.8%, GLM-5.3-Flash 35.8%, Qwen3.8-Max-0902 27%; Senior SWE-bench (mini-SWE-agent) DeepSeek V4.1 Flash 22.7%, MiniMax M3 21.1%, Kimi K3 20.2%. So the evidence is thin and harness-dependent, but not GLM-only [corrected 2026-10-20: snorkel.ai/leaderboard/agentic-coding-2/, /swe-bench-cli/, /terminal-bench/ (TB 4.0), /senior-swe-bench/, fetched 2026-10-20]. Pick by price, ToS and data policy first; then run a small local A/B on this repo's own phases.
6. Data jurisdiction varies a lot. **Alibaba** ("will never use your data for model training", regions in the EU, US and Singapore) and **OpenRouter** (no prompt storage unless opted in, ZDR routing) are the strongest on confidentiality. **Z.ai** (Singapore; its API data-processing terms say API content is not stored) is next. **Moonshot** says it may use Content to improve its services; a no-training arrangement exists only for enterprise customers. **DeepSeek** stores data in China under PRC law and its platform terms make no promise against training. For code that should not leave a known jurisdiction, use a ZDR host on OpenRouter (EU-only routing via `eu.openrouter.ai`) or Qwen3.8 Max / Flash under Alibaba's **US** deployment scope in Virginia. Alibaba hosts DeepSeek and Kimi in Virginia and Frankfurt only under the Global (or International) deployment scope, so request data is stored in-region but inference may run outside it; Frankfurt offers qwen3.8-max only under Global scope too [corrected 2026-10-20: alibabacloud.com/help/en/model-studio/model-pricing (updated 2026-10-19), "Deployment scope" column per region; model-studio/regions: "Service deployment scope: Determines the inference execution location"].
7. Best fit per role, with low confidence because of the benchmark gaps: **implementer** = GLM-5.3 (plan through ZCode, as today) with DeepSeek V4 Pro (pay-as-you-go, off-peak) as a cheap second family; **reviewer** (must be a different family from the writer) = Kimi K3 or Qwen3.8 Max at max effort, or the existing Opus/Codex Sol reviewers; **cheap utility** = DeepSeek Flash, GPT-6 Luna or MiniMax M3.1 Flash.

Evidence legend: `[docs:<url>]` = official page or API, fetched 2026-10-20 unless dated; `[local-run]` = read on this machine; `[third-party:<url>]`; `[unverified]`. `ZCode-cfg` means `/Applications/ZCode.app/Contents/Resources/config/provider/zcode-builtin.json` (ZCode 3.15.1, schema 1, revision 31, file mtime 2026-10-10). This is Z.ai's own built-in catalog of third-party provider templates, which I read as a second, independent snapshot [local-run]. Prices are USD per 1M tokens.

**Reliability assessment.** The report holds up well where it matters most. Every endpoint URL, every price I could check against a first-party page, every model id and context window, and every terms-of-service quote matched the source. The quotes are verbatim, apart from one OpenRouter paraphrase, now fixed. The Terminal-Bench 3.0 figure is exact. The errors fall into three groups. (1) One evidence gap changes the conclusions: the report missed Snorkel's other coding leaderboards. Those list Kimi K3, DeepSeek V4 Pro, Qwen 3.8 Max and MiniMax M3, so "GLM-5.3 is the only open model with an independent score" is false. They also weaken the case for Qwen3.8 Max as a reviewer (14.7%, with 77.7% agent timeouts) and for DeepSeek V4 Pro as an implementer (14.8%). (2) One data-residency recommendation was wrong: Alibaba serves DeepSeek and Kimi in Virginia and Frankfurt only under Global or International scope, so routing through those regions does not keep inference in the region. (3) Small API-detail errors: Kimi `tool_choice` has no `tool` type, K2.7 Code cannot turn thinking off, Kimi images need `ms://` file ids, Z.ai "Compatible" key scope, Qwen cached prices taken from OpenRouter. The MiniMax terms the report called unreadable were readable and are now summarised in §2.4. The headline verdict stands: use pay-as-you-go keys by default, make plan keys opt-in, and treat Kimi Code and both Alibaba plans as non-compliant for unattended dispatch. Overall reliability: high for protocols, prices and terms; medium for the benchmark and data-jurisdiction guidance before these corrections.
