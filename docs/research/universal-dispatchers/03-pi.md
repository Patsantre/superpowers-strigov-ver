## Bottom line

- **Identity.** pi now lives at **earendil-works/pi**; `badlogic/pi-mono` redirects there. The package is **`@earendil-works/pi-coding-agent` v1.3.0** (2026-10-15), MIT. The old `@mariozechner/pi-coding-agent` is deprecated at 0.73.1. The project is very active: 1.0.0 shipped 2026-10-01, and seven more releases followed within two weeks (1.0.1, 1.0.2, 1.0.3, 1.0.4, 1.1.0, 1.2.0, 1.3.0) [corrected 2026-10-20: `gh api repos/earendil-works/pi/releases` and `npm view @earendil-works/pi-coding-agent time` list seven releases between 2026-10-03 and 2026-10-15, not five] [S:ca/package.json] [S:ca/CHANGELOG.md] [local-run: `npm view`, `gh api`].
- **Best job-runner mode: `pi --mode json`**, one detached process per turn:
  - The prompt is fed from a file on stdin.
  - `--session-dir <state> --session-id <jobId>` give a deterministic session id and resume key.
  - The job record is built from the JSONL stream. Line 1 is the session header, which carries the id. The last assistant `message_end` is the final text. `stopReason`/`errorMessage` give the verdict and `usage.cost` gives the cost.
  - `-p` is too opaque: no session id, no usage, and it silently prints nothing when the run ends on a tool result.
  - `--mode rpc` suits a resident broker, which is a possible phase 2.
- **Provider breadth is the main reason to adopt pi.** It has 40+ built-in providers, including DeepSeek, MiniMax, Qwen Token Plan, Kimi, Z.ai, OpenRouter, OpenCode Zen/Go, Bedrock, Vertex and Azure. `models.json` adds any OpenAI-Completions, OpenAI-Responses, Anthropic-Messages or Google-compatible endpoint, which covers Ollama, LM Studio, vLLM and SGLang. A built-in llama.cpp router integration is also included. One adapter could cover most "bring your own key" or local-model wishes.
- **Isolation is good:**
  - `PI_CODING_AGENT_DIR` moves settings, auth, models, MCP, extensions, skills, prompts, trust and sessions.
  - `--no-approve -ne -ns -np --no-mcp [-nc]` stop the target repo and the user's home from injecting resources.
  - An env allowlist is still needed, because pi falls back to provider env vars.
- **pi has no permission system and no sandbox (by design).** Read-only reviewer = `--tools read,grep,find,ls --no-mcp -ne`, which removes the means to write rather than enforcing a policy.
- **Policy blockers for this plugin:**
  - pi's Anthropic subscription OAuth **impersonates Claude Code**: `user-agent: claude-cli/2.1.280`, `x-app: cli`, a "You are Claude Code…" system block, and Claude Code's OAuth client id.
  - Its GitHub Copilot login impersonates VS Code Copilot Chat.
  - Both break the plugin's truthful-client-identification rule.
  - pi's `zai` provider sends GLM traffic outside Z.ai's own harness.
  - So the adapter must default to API-key providers and keep a provider denylist [S:ai/src/api/anthropic-messages.ts:95-96,1049-1069,1227-1236] [S:ai/src/auth/oauth/github-copilot.ts:11-17].
- **Secrets are visible to the agent** unless the run is OS-sandboxed: the bash tool inherits the full environment, and the agent can `cat` `auth.json`. SDK embedding with `setRuntimeApiKey` keeps the key in process memory only.
- **Verdict:** a strong candidate for a generic `pi-dispatch` adapter (API-key providers only). It is about as much work as `zcode-dispatch` and reuses its job-record, lock, reaper and classifier skeleton.

## 2. Headless invocation

### 2.1 Modes

| Mode | Selected by | Lifetime | stdout | Use |
|---|---|---|---|---|
| Print | `-p/--print`, **or implicitly whenever stdin or stdout is not a TTY** (no `--mode`) | one invocation | only the text blocks of the **last** assistant message | simple scripts |
| JSON | `--mode json` | one invocation (all prompts given at start) | strict JSONL: session header, then every session event | **background job runner (recommended)** |
| RPC | `--mode rpc` | long-lived, until stdin closes or SIGTERM | JSONL responses and events; commands on stdin | a resident broker, steering, multi-turn without respawn |
| SDK | `import { createAgentSession }` | in-process | events via `session.subscribe` | an embedded runner (see §16.6) |

Evidence: [S:ca/docs/cli.md#invocation-and-output] [S:ca/docs/cli-integration.md] [S:ca/src/main.ts:112-122 resolveAppMode].

### 2.2 Prompt transport

| Transport | Behaviour | Evidence |
|---|---|---|
| argv `messages…` | The first positional becomes the initial prompt. **Each further positional is sent as a separate sequential prompt (a new turn).** `-p` takes the next argument as the prompt unless it starts with `-` or `@`. Use `--` before a prompt that begins with `-`. | [S:ca/src/cli/args.ts:177-183] [S:ca/src/modes/print-mode.ts:131-137] [S:ca/docs/cli.md] |
| stdin (piped) | Read fully until EOF, **trimmed**, and prepended to the first prompt. Skipped in RPC mode. If stdin is a pipe that never closes, pi blocks forever. | [S:ca/src/main.ts:80-97,894-900] [S:ca/src/cli/initial-message.ts] |
| `@path` | A text file or image is included in the first prompt, resolved from cwd. Rejected in RPC mode. | [S:ca/docs/cli.md] [S:ca/src/cli/args.ts:249] |
| Size limits | pi itself sets no prompt-size cap; none was found in the args/initial-message code. argv is bounded by the OS (Linux `MAX_ARG_STRLEN` 128 KiB per argument; macOS `ARG_MAX` ~1 MiB for argv+env) [verified 2026-10-20: `getconf ARG_MAX` = 1048576 on this Mac; Linux `include/uapi/linux/binfmts.h` defines `MAX_ARG_STRLEN (PAGE_SIZE * 32)`, i.e. 128 KiB with 4 KiB pages and larger on 16/64 KiB-page kernels]. **Use a stdin redirect from the prompt file.** | [S:ca/src/cli/initial-message.ts] |

Prompts that start with `/` are treated as extension commands, prompt templates (`/name`) or skill commands (`/skill:name`) and expanded before they reach the model. With `-ne -np -ns` nothing can match, but avoid a leading `/` anyway [S:ca/docs/rpc-commands.md#prompt] [S:ca/docs/sdk.md#prompting].

### 2.3 Canonical headless command lines

```bash
# Implementer turn (fresh), JSON events, prompt from file
PI_CODING_AGENT_DIR="$STATE/pi/profiles/$PROFILE" PI_OFFLINE=1 PI_TELEMETRY=0 \
pi --mode json --model "$PROVIDER/$MODEL_ID" --thinking high \
   --session-dir "$STATE/pi/sessions" --session-id "$JOB_ID" \
   --no-approve -ne -ns -np --no-mcp \
   --append-system-prompt "$PLUGIN/prompts/implementer-contract.md" \
   < "$JOB_DIR/prompt.md" > "$JOB_DIR/events.1.jsonl" 2> "$JOB_DIR/stderr.1.log"

# Resume (same cwd, same session dir, same id → appends to the session)
pi --mode json ... --session-dir "$STATE/pi/sessions" --session-id "$JOB_ID" < followup.md > events.2.jsonl

# Read-only reviewer (fresh, ephemeral)
pi --mode json --no-session --tools read,grep,find,ls --no-mcp -ne -ns -np --no-approve --model ... < review.md

# Simplest one-shot
pi -p "Summarize this repository"
```

Flags exist per [S:ca/docs/cli.md] and [S:ca/src/cli/args.ts:83-247]. `PI_OFFLINE`, `PI_TELEMETRY` and `PI_CODING_AGENT_DIR` come from [S:ca/docs/environment-variables.md]. The exact combination above has not been run (pi is not installed) [unverified as a whole].

## 3. Output and final-message extraction

### 3.1 JSON mode (`--mode json`)

- **Framing.** Strict JSONL: one object per record, split only on LF, strip an optional CR. **Do not use Node `readline`**, which also splits on U+2028/U+2029. stdout is reserved for records; diagnostics go to stderr. Read continuously, because pi honours stdout backpressure [S:ca/docs/json.md#framing-and-process-io].
- **Line 1** is the session header: `{"type":"session","version":3,"id":"<uuid|--session-id>","timestamp":"…","cwd":"…"}`. The header is written before any event [S:ca/src/modes/print-mode.ts:122-127] [S:ca/docs/json.md#session-header].
- **Event types:**

| Event | Key fields | Use for the job runner |
|---|---|---|
| `agent_start` / `agent_end` | `messages`, `willRetry` | One low-level run ended. **Not final:** retry, compaction or a queue may follow. |
| `agent_settled` | `aborted` (since 1.1.0) | **The terminal marker.** pi does no more automatic work. |
| `turn_start` / `turn_end` | `message`, `toolResults` | turn counting |
| `message_start` / `message_update` / `message_end` | `message`; update carries `usage` and a delta-only `assistantMessageEvent` (`text_delta`, `thinking_delta`, `toolcall_*`) | **`message_end` is the authoritative message.** |
| `tool_execution_start/update/end` | `toolCallId`, `toolName`, `args`, `result`, `isError`, `durationMs` | progress line for `status` |
| `compaction_start/end` | `reason` = manual/threshold/overflow; `result{summary,tokensBefore,estimatedTokensAfter,usage}`; `errorMessage` | cost, diagnostics |
| `auto_retry_start/end` | `attempt`, `maxAttempts`, `delayMs`, `errorMessage`; end has `success` and `finalError` | rate-limit and transient-error classification |
| `queue_update`, `entry_appended`, `session_info_changed`, `thinking_level_changed`, `summarization_retry_*` | — | ignore |

Evidence: [S:ca/docs/json.md] [S:ca/CHANGELOG.md#1.1.0 "Added `aborted` to `agent_settled`"].

- **Final message algorithm.**
  1. Take the last `message_end` whose `message.role == "assistant"`.
  2. Read `stopReason` from `"stop"|"length"|"toolUse"|"error"|"aborted"|"deferred"`.
  3. Read `errorMessage`.
  4. Final text = join the `content[]` blocks with `type=="text"`, skipping `thinking` and `toolCall` blocks.
  5. The status token is line 1 of that text.

  Evidence: [S:ca/docs/message-types.md#assistantmessage].
- **Exit code in JSON mode:** *"A failed or aborted assistant response appears in the event stream but does not by itself produce a nonzero exit status"*. A non-zero exit means only that the invocation threw [S:ca/docs/cli-integration.md#stream-json-events]. **The adapter must classify from the events.**

### 3.2 Print mode (`-p`)

- The last state message is checked [S:ca/src/modes/print-mode.ts:139-160]:
  - If it is an assistant message with `stopReason` `error` or `aborted`, `errorMessage` goes to stderr and the exit code is 1.
  - Otherwise every text block is written to stdout, each followed by `\n`.
  - With `stopReason=length` the text is still printed, plus the stderr warning `Response was truncated: the model reached its output token limit.`, and the exit code is 1 (fixed in 1.2.0, #10799).
- **Gotcha:** if the last message is not an assistant message, for example a run that ends on a `terminate: true` tool result, nothing is printed and the exit code is **0** [S:ca/src/modes/print-mode.ts:141-143].
- No session id, usage or progress is exposed [S:ca/docs/cli-integration.md#print-to-stdout].

### 5.3 Custom endpoints via `<agent-dir>/models.json`

```json
{
  "$schema": "https://pi.dev/schemas/models.schema.json",
  "providers": {
    "ollama": { "baseUrl": "http://localhost:11434/v1", "api": "openai-completions",
                "apiKey": "ollama", "models": [ { "id": "qwen2.5-coder:7b" } ] }
  }
}
```

- Provider fields: `name, baseUrl, apiKey, api, oauth, headers, compat, authHeader, models[], modelOverrides{}`.
- Model fields: `id, name, api, baseUrl, reasoning, thinkingLevelMap, input, inputLimits, cost, promptCache, contextWindow, maxTokens, samplingParams, samplingParamsByThinkingLevel, headers, compat` [S:ca/schemas/models.schema.json].

- Values in `apiKey` and `headers` support `$VAR`/`${VAR}`, a literal, or `!command`. In `models.json` the command runs on every request and is not cached [S:ca/docs/models.md#configure-a-compatible-endpoint].
- `compat` knobs cover reasoning wire formats for local and third-party servers. `thinkingFormat` takes: openai, openrouter, deepseek, together, baseten, zai, qwen, chat-template, qwen-chat-template, string-thinking, ant-ling. ## 10. Concurrency and cancellation

- **Process tree:**
  - pi → `bash` tool children are spawned with **`detached: true`** (their own process group) on non-Windows [S:ca/src/core/tools/bash.ts:112-115].
  - pi tracks their PIDs. On SIGTERM/SIGHUP it runs `killTrackedDetachedChildren()`, which sends `process.kill(-pid, SIGKILL)` per group (`taskkill /F /T` on Windows), disposes the runtime and exits 143/129 [S:ca/src/utils/shell.ts:164-215] [S:ca/src/modes/print-mode.ts:50-66].
  - Consequence: if pi is SIGKILLed or gets SIGINT, the bash process groups are orphaned.
- **Runner recipe:**
  1. Spawn pi detached (its own pgid).
  2. Cancel = SIGTERM to the pi pid → grace (e.g. 5-10 s) → SIGKILL to the pi pgid.
  3. Sweep orphans: before the kill, snapshot the descendant pids (walk `ps -o pid,ppid`) and SIGKILL any still alive afterwards.
- **RPC cancellation** is cooperative: the `abort` command waits for idle; closing stdin shuts down cleanly [S:ca/docs/rpc-commands.md#abort] [S:ca/docs/rpc.md#shutdown].
- **Servers and ports:** none in headless runs. OAuth callback listeners exist only during `/login` (Anthropic 53692 with fallback, OpenAI 1455). MCP stdio servers are spawned only if MCP is configured and enabled [S:ai/src/auth/oauth/anthropic.ts:20] [S:ai/src/auth/oauth/openai-chatgpt.ts:23].
- **Locks:** `auth.json` uses `proper-lockfile`. Session files are created with `wx` (an id collision fails). **There is no workspace lock**: two pi writers in one tree would conflict, so the plugin's per-workspace reservation must wrap pi. Codemode workers are capped at 2 per process [S:ca/src/core/auth-storage.ts] [S:ca/src/core/session-manager.ts:1177] [S:ca/CHANGELOG.md#1.3.0].
- **Parallel jobs:** use distinct `--session-id`s; never `--continue`.

## 12. Structured output / verdict support

- **No native response schema.** JSON mode is an event stream, "not a single JSON result or a constraint on the format of the model's response" [S:ca/docs/cli-integration.md#stream-json-events]. pi has no flag equivalent to `--output-schema`.

## 15. Gotchas

1. **The name and scope changed.** Search results and memory point at `badlogic/pi-mono` and `@mariozechner/pi-coding-agent` (deprecated at 0.73.1). Pin `@earendil-works/pi-coding-agent@1.3.0`. The pi.dev installer pins transitive deps; npm does not [S:/README.md#supply-chain-hardening].
2. Non-TTY stdout **implicitly** selects print mode. Always pass `--mode json` explicitly [S:ca/src/main.ts:119].
3. stdin left as an open pipe hangs print/json mode (it reads to EOF). Spawn with stdin = prompt file or `/dev/null` [S:ca/src/main.ts:80-97].
4. Extra positional args become **extra turns**, not extra text [S:ca/src/modes/print-mode.ts:135-137].
5. JSON mode exits 0 on provider errors, so classify from events. Print mode exits 0 with empty stdout when the run ends on a tool result [S:ca/docs/cli-integration.md] [S:ca/src/modes/print-mode.ts:141].
6. `--session-id` with an unknown id silently **creates** a new session (warning only). Verify that the session file exists before a resume [S:ca/src/main.ts:436-447].
7. `--session <partial>` can hit a session in another project and open an **interactive confirm**. Use only `--session-id` plus `--session-dir` [S:ca/src/main.ts:390-399].
8. With a custom `--session-dir`, lookup filters by the header `cwd`, so resume must run from the same cwd (worktree path) [S:ca/src/core/session-manager.ts:1874-1890].
9. `--provider p --model typo` → "Using custom model id" warning, then a remote 404. Validate ids with `--list-models` in `doctor` [S:ca/src/core/model-resolver.ts:526].
10. **SIGINT does not clean up**; use SIGTERM. SIGKILL orphans bash process groups (§10).
11. Provider env vars leak in: an isolated agent dir does not stop pi from using the user's exported `OPENAI_API_KEY` and similar. Use an env allowlist [S:ca/docs/models.md#authenticate].
12. Context files load **without trust**. `CLAUDE.md` in this plugin's target repos would be fed to a non-Claude model. Decide per role whether to keep them or pass `-nc` [S:ca/docs/security.md].
13. `~/.agents/skills` is a home-level skill dir outside the agent dir. Use `-ns` [S:ca/docs/skills.md].
14. `grep`/`find` tools download fd/rg from GitHub if missing (blocked by `PI_OFFLINE=1`, after which they degrade) [S:ca/src/utils/tools-manager.ts].
15. The JSONL must not be split with Node `readline` (U+2028/2029) [S:ca/docs/json.md].
16. API churn is high. Breaking changes in 1.0.3 (Azure provider rename), 1.2.0 (schemas, `before_agent_start`) and 1.3.0 (Kimi base URL must include `/v1`). Pin the version and re-verify on upgrade [S:ca/CHANGELOG.md].
17. `settings.json` can be mutated by pi (e.g. the ChatGPT `deviceId`, Ctrl+S model defaults). Keep each profile's agent dir wrapper-owned [S:ca/CHANGELOG.md].
18. `--tools` does not remove MCP tools unless an entry starts with `mcp__`. A "read-only" list still exposes MCP tools without `--no-mcp` [S:ca/docs/cli.md#mcp-tools].
19. On Windows, the bash tool requires Git Bash (or `shellPath`). Process-group kill differs there (`taskkill /T`) [S:ca/docs/windows.md].

- exit codes 0/1/2.

See `00-current-architecture.md` §1.

### 16.1 Profiles (user-configurable channels)

`$CLAUDE_PLUGIN_DATA/pi/profiles/<name>/` is the agent dir (0700). It contains `models.json` (custom endpoints), `auth.json` (written only by `pi-dispatch api-key set <profile> <provider>`, which reads the key from stdin or a TTY, never from chat; or a `"!security find-generic-password …"` key) and `settings.json`. A wrapper-owned `profile.json` adds:

```json
{ "provider": "deepseek", "model": "<model-id>", "thinking": "high",
  "family": "deepseek", "roles": ["implementer","reviewer"],
  "contextFiles": false, "timeoutMin": 60 }
```

Recommended `settings.json` contents: `{"enableInstallTelemetry":false,"defaultProjectTrust":"never","compaction":{"enabled":true},"retry":{"maxRetries":3},"cacheWarming":"off"}`. The keys come from [S:ca/docs/settings.md]; the values are a recommendation.

`task` refuses (exit 2) in these cases:
- the provider is on the denylist (`anthropic` with OAuth, `github-copilot`, `openai-codex`, `zai*`, pending the ToS matrix);
- `pi auth check` reports `authType:"oauth"` for a provider that is not allowlisted;
- the profile's family equals the reviewer's family (family rule).

### 16.3 Why not `-p` or RPC for v1

- `-p` loses the session id, usage, progress and error detail, and it has the empty-output exit-0 hole.
- RPC needs a long-lived parent holding stdin, which only pays off for steering or follow-ups without respawn (the codex-companion broker pattern). Its extras are `get_session_stats`, `get_last_assistant_text`, `abort`, `steer`/`follow_up` and `set_auto_retry`, and the exported `RpcClient` (`promptAndWait`) makes it cheap later [S:ca/docs/rpc.md] [S:ca/docs/rpc-commands.md] [S:ca/docs/cli-integration.md#control-pi-with-rpc].

### 16.4 Family rule

Family must be derived from the **model**, not the harness:
- `anthropic/*`, `amazon-bedrock/*anthropic*`, `openrouter/anthropic/*` = Claude family, so they **cannot** be the implementer when Opus reviews.
- `openai*`, `azure/gpt-*` and `openai-codex` = the same family as the Codex channel.

Keep an explicit `family` field in the profile and validate it against a provider/model prefix table.

### 16.5 Effort mapping

Plugin effort → `--thinking` (`off…max`). pi clamps to model support, so record `thinkingLevel` from the assistant message (`providerThinkingLevel`/`thinkingLevel`) for the job record [S:ca/docs/message-types.md].

### 16.6 SDK alternative (phase 2)

- The runner is a plugin Node script that imports `@earendil-works/pi-coding-agent`. It does:
  - `ModelRuntime.create({authPath, modelsPath})` + `setRuntimeApiKey(provider, key)`;
  - `createAgentSession({cwd, agentDir, model, thinkingLevel, modelRuntime, resourceLoader /* empty */, tools, sessionManager: SessionManager.create(cwd, dir, {id}), settingsManager: SettingsManager.inMemory({...})})`;
  - `session.subscribe(...)`, then `await session.prompt(text)`, then `session.dispose()` [S:ca/docs/sdk.md] [S:ca/examples/sdk/12-full-control.ts].
- Pros:
  - The key is in memory only.
  - A custom `createBashTool(cwd, {spawnHook})` can scrub the env [S:ca/docs/environment-variables.md#custom-shell-tools].
  - No CLI-parsing quirks; direct usage stats.
- Cons:
  - The plugin must vendor a large npm tree (supply-chain review; `--ignore-scripts`).
  - It tracks a fast-moving API.
  - Built-in extensions (MCP, codemode) are not loaded by default in the SDK, which is fine here.
